# 文档维护规则

这份文档只回答“新信息该写哪里、旧信息什么时候删”。目标是防止入口文档再次长成历史长文。

## 唯一归属

| 信息类型 | 写入位置 |
| --- | --- |
| 当前结论、冻结默认、winner、判读规则 | `docs/status/` |
| 接手下一步、当前风险、最短阅读路线 | `docs/agent/handoff.md` |
| 命令、脚本、运行坑位 | `docs/agent/workflows.md` |
| 双机同步、远程任务、运行资产边界 | `docs/agent/remote-ops.md` |
| 代码目录职责、迁移边界 | `docs/agent/code-map.md` |
| 实验证据、论文调研、设计理由 | `docs/research/` |
| 人机协作、判断过程、个人复盘 | `docs/reflections/` |
| 被新结论覆盖但仍值得保留的旧文档 | `docs/archive/` |

## 去重规则

- 同一个事实只允许有一个权威落点。
- 入口文档可以摘要事实，但必须链接到权威落点。
- 命令不要同时写进 `handoff.md`、`README.md` 和状态页。
- 状态页不展开完整研究论证，只保留结论、口径、关键证据路径。
- 研究页开头必须说明它是否仍影响当前主线。

## 归档规则

满足任一条件就归档：

- 文件主要描述的计划已被 `status/` 中的新结论覆盖。
- 文件只为兼容旧路径存在，没有独立信息。
- 文件混合了历史过程和当前操作，且当前操作已经迁入 `agent/` 或 `status/`。

归档后在 `docs/archive/README.md` 加一行说明。不要在活跃目录保留重复 stub。

## 更新流程

1. 先判断信息类型，找到唯一落点。
2. 如果会改变当前默认，先更新对应 `status/` 文件。
3. 再把 `handoff.md` 压缩更新为“下一步怎么接”。
4. 如果新增研究长文，只在 `research/README.md` 加一行索引。
5. 最后跑一次链接和路径检查。
